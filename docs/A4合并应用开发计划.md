# A4 合并助手（桌面应用）开发计划

> 基于 `merge_to_a4_wps.py` 重构为 Windows 桌面应用
> 技术栈：Python 3.11+ / PySide6（Qt6）/ PyInstaller 单文件打包 / git 版本控制
> 目标用户：自己 + 同事（非技术用户，界面傻瓜化）
> 范围：标准版 + 精简增强项（目标勾选、运行报告、打包版禁用自动安装）+ 工程加固（见 3.11）
> 转换引擎：**WPS 主引擎 + 纯 Python 兜底**，不依赖微软 Office（见第 3.6 节）
> 输出位置：**双模式**——①生成到各子文件夹内（现状）②统一输出到指定文件夹（见第 3.7 节）
> 明确砍掉：PDF 书签、金山专有格式兼容开发（见第 3.9 节）；LibreOffice 后端第一版不做（后置）

## 1. 总体架构

### 1.1 分层设计（核心原则：逻辑与界面彻底分离）

```
a4merger/
├── core/                    # 从 merge_to_a4_wps.py 抽取的业务核心（不 import 任何 Qt）
│   ├── __init__.py
│   ├── types.py             # 结构化类型：MergeResult、FileFailure、进度回调接口
│   ├── collect.py           # 文件收集、自然排序、同名成品识别、输出目录/报告文件排除、长路径兜底
│   ├── encrypt.py           # 加密 PDF / Office 检测、解密、msoffcrypto 调用
│   ├── converters/          # 转换引擎抽象层（详细设计见 3.6 节）
│   │   ├── base.py          # Converter 统一接口（convert(src, out, opts) -> bool）
│   │   ├── manager.py       # 引擎探测与降级选择（WPS → 纯 Python）
│   │   ├── backend_wps.py   # 后端A：WPS COM（原 WPS_WORKER_PS 原样迁移，支持中途终止）
│   │   └── backend_native.py # 后端B：纯 Python（图片 Pillow / 文本 fpdf2 / PDF pypdf）
│   ├── merge.py             # pypdf A4 排版合并（原样迁移）+ 页级回调 + 损坏 PDF 容错（3.10）
│   ├── report.py            # 运行报告生成（合并报告.txt，UTF-8-sig）
│   ├── runner.py            # 任务编排（原 main / process_folder 的逻辑）
│   └── deps.py              # 依赖保障（开发模式 pip 自动安装；打包后禁用，见 3.8.3）
├── app/                     # Qt 界面层
│   ├── main.py              # 程序入口（含单实例检查，见 3.11.8）
│   ├── ui_main.py           # 主窗口（参数表单 + 目标勾选 + 日志 + 进度）
│   ├── worker.py            # QThread 后台执行线程，信号槽通信；取消时终止子进程（3.11.4）
│   ├── diagnostics.py       # debug 日志落盘、sys.excepthook 兜底、诊断包导出（3.11.7）
│   ├── settings.py          # QSettings 配置持久化（密码走 DPAPI，见 3.11.9）
│   └── dialogs.py           # 密码输入、失败清单、结果总结、关于（含版本号，3.11.10）
├── cli.py                   # 原命令行入口（薄封装 core，保留原始参数与行为，新增
│                            #   --output-dir / --only（相对路径）/ --no-report）
├── run_gui.py               # 开发期直接运行 GUI 的入口
├── legacy/                  # 原脚本冻结基线（merge_to_a4_wps.py 永不修改，tag baseline-v0）
├── requirements.txt         # 运行时依赖全量锁定（见 3.11.12）
├── requirements-dev.txt     # 开发/打包/样例生成工具锁定（-r requirements.txt）
├── build/
│   ├── a4merger.spec        # PyInstaller 配置（含字体 datas、version resource、manifest 长路径声明）
│   └── icon.ico             # 应用图标
├── fonts/                   # 开源中文字体（思源/Noto，OFL 授权，见 3.11.1）
└── tests/                   # pytest 黄金样本回归（见 3.11.13）
```

### 1.2 原脚本的复用与改造点

| 原脚本内容 | 处理方式 |
|---|---|
| WPS PowerShell 转换脚本（WPS_WORKER_PS） | **原样保留**（已充分验证），移入 core/converters/backend_wps.py；其上增加统一 Converter 接口与 manager 探测/降级；**支持中途终止（取消时杀子进程，见 3.11.4）** |
| A4 排版合并（fit_box / merge_to_a4） | 原样保留，移入 core/merge.py；**新增页级进度回调、损坏 PDF 容错（无效批注剥离 + 单页/单文件失败隔离，见 3.10）** |
| 文件收集 / 自然排序 / 同名成品识别 | 原样保留，移入 core/collect.py；新增"排除指定目录树"与"排除合并报告文件"能力；成品识别按**输出模板动态计算**——模板改为 `【合并】{folder}.pdf` 后，历史遗留的无标记成品（如 `张三.pdf`）不再被识别为"上次成品"，将按普通素材处理（属预期行为，文档明示，见 3.7） |
| 图片 Pillow 兜底（pillow_image_to_pdf） | 原样保留（已含 `ImageOps.exif_transpose` 处理 EXIF 方向，见 3.11.2） |
| 加密检测与解密 | 原样保留，移入 core/encrypt.py |
| `process_folder` / `main` 编排 | 改造成 `runner.py` 的可重入函数；增加**目标子集（--only，按相对路径）**；结束后生成**运行报告** |
| 输出文件位置（out_path = 文件夹内） | 抽成可配置的"**输出计划**"：模式A＝各子文件夹内（原逻辑不变）；模式B＝统一输出目录（新增 `--output-dir`），含命名冲突处理、扫描排除、上次成品识别 |
| `print(flush=True)` 日志 | 改为**回调**：`on_log(level, text)`，GUI 接信号；同时写入 debug 日志文件（3.11.7） |
| `input()` 交互式密码询问 | 改为**回调**：向 GUI 请求密码；无 GUI 时退化为原交互或跳过 |
| 依赖自动安装（ensure_module） | 保留但加 `sys.frozen` 判定：**打包后直接报"依赖缺失请重装应用"，不再尝试 pip**（见 3.8.3） |

### 1.3 原脚本保留不变

- `merge_to_a4_wps.py` 原文件**不修改**，立即提交 git 并打 tag `baseline-v0` 冻结为对照基线（见 3.11.11）；
- 新工程从它拷贝一份重构为 core 包，保证任何时刻 CLI 都能独立工作。

### 2.2 执行体验

- **两级进度条**：文件夹级（N 个目标完成数）+ 文件级（当前文件夹内文件转换进度，按转换批次回报）；
- **实时日志区**：带时间戳、按级别着色（成功绿 / 警告黄 / 失败红 / 信息灰），支持"自动滚动到底部"开关与**容量截断**（超过约 5000 行自动裁剪，防长任务内存膨胀）；每个文件记录实际使用的转换引擎**与输出目标路径**；**日志同时落盘为 debug 日志文件**（3.11.7）；
- **运行中可取消**：点击取消后**立即终止正在运行的 PowerShell/WPS 子进程并清理本批中间文件**，承诺数秒内响应（见 3.11.4），已完成的文件夹保留结果；
- **单实例**：重复启动时提示并激活已有窗口（见 3.11.8）；
- **密码弹窗**：核心遇到加密文件且未预置密码时，弹窗询问（回车跳过；默认建议勾选"直接跳过"以避免非技术用户卡住）；
- **统一输出模式**：输出目录不存在时自动创建，创建失败提前拦截并中文提示；
- **完成总结对话框**：
  - 成功列表（文件夹 → 页数 → 文件大小 → 输出路径）
  - 失败清单（文件名 + 原因 + 跳过的页数；**单个文件/单页失败不中断其它文件**，双击可打开所在文件夹）
  - 被跳过的"同名成品 PDF"清单（提示如何包含）与忽略的不支持类型清单
  - 按钮：打开输出目录（按当前模式定位）、**打开运行报告**、失败项清单可导出 TXT
- **运行报告**：结束后自动生成 `合并报告.txt`（UTF-8-sig，记事本直接可读），含运行参数、目标清单、失败/跳过明细（见 3.8.2）；
- **配置记忆**：QSettings 记住根目录、**目标勾选**、输出模式与统一输出目录、所有参数、引擎选择、窗口大小位置；密码默认不保存，勾选记住时走 DPAPI 加密（见 3.11.9）；
- **主窗口状态栏**：显示**引擎探测结果**（WPS 可用 / 纯 Python 兜底）、当前任务状态、**应用版本号**（见 3.11.10）；
- **关于对话框**：版本号、构建时间、依赖版本、更新方式说明（整包替换 exe）。

## 3. 关键技术方案

### 3.1 线程模型

```
GUI 主线程（Qt 事件循环）
   └── Worker(QThread) ── 运行 core.runner 全程（含 subprocess 调 PowerShell/WPS）
        进度/日志/结果 ──Qt 信号──▶ 主线程 更新界面
        密码请求 ──信号──▶ 主线程弹框 ──回传──▶ Worker 继续
        取消 ──主线程设置标志──▶ Worker 立即终止子进程（3.11.4）
```

- core 层只接受纯 Python 回调（`on_log` / `on_progress` / `ask_password` / `should_cancel`），不依赖 Qt，便于单测；
- GUI 层用 `Signal` 包装回调，跨线程自动排队；
- 转换本身都是 `subprocess`（WPS 走 PowerShell，改用 `Popen` 持有句柄以便取消时 terminate），天然阻塞且可被超时控制，**不会阻塞 Qt 事件循环**（运行在 Worker 线程）。

### 3.2 密码交互的改造

- 原 `ask_password(input())` 拆成回调 `ask_password(path, verify) -> str | None`；
- GUI 实现：先尝试预置密码列表（与脚本一致），都不行且未勾选"直接跳过"时弹模态输入框（3 次机会）；
- CLI 实现：保持原来的 `input()` 交互；
- 密码记忆：默认不保存；勾选"记住密码"时用 Windows DPAPI（ctypes 调 CryptProtectData）加密后存 QSettings（见 3.11.9）。

### 3.3 进度上报粒度

- 文件夹开始/结束（1 个进度单位）；
- 文件夹内文件级：按转换批次汇报"已转换 n/N"（原脚本已有 1~3 轮批量重试机制）；
- 合并阶段汇报"正在排版第 n/N 页"（`merge_to_a4` 增加可选页级回调）。

### 3.4 打包（PyInstaller）

- 命令：`pyinstaller --onefile --windowed --name A4合并助手 build/a4merger.spec`；
- **--windowed 必须**：无控制台窗口，日志全走 GUI + debug 日志文件；
- 隐藏导入：`pypdf`、`Pillow`、`fpdf2`、`msoffcrypto` 需在 spec 中显式收集（Pillow 用 `collect_submodules`）；
- **资源文件**：开源中文字体（`fonts/`，OFL 授权）进 datas（见 3.11.1）；
- **version resource**：`--version-file` 写入文件版本 1.0.0.0，关于对话框显示版本号与构建时间（见 3.11.10）；
- **longPathAware**：manifest 声明长路径感知 + 启动探测系统 `LongPathsEnabled`（见 3.11.3）；
- PowerShell 调用：内嵌字符串，无外部资源文件，onefile 解包到临时目录不影响；
- 原脚本"默认根目录 = 脚本所在目录"的语义在 GUI 版中**改为显式选择目录**（打包后没有脚本路径可依）；
- 加密 Office 解密用 msoffcrypto 是纯 Python，随包分发无 DLL 问题；
- **依赖全部内置，打包版绝不触发 pip 安装**（`sys.frozen` 判定，见 3.8.3），避免同事机器上弹黑框/失败；
- **只交付单 exe**，无任何捆绑安装包；更新方式＝整包替换 exe；
- 建议 Python 3.11 打包（PySide6 与 PyInstaller 兼容性最好），目标平台 Win10/11 x64；**打包机环境与 requirements.txt 一致**（见 3.11.12）。

### 3.5 环境检测与友好报错

- 启动时检测：WPS 可用性（COM 用轻量 PowerShell 探测）、根目录可写性、**系统长路径支持状态**；
- 缺失依赖（仅开发模式）：保留自动安装逻辑，但 GUI 中提示安装结果而非静默；**打包版直接提示"请重新安装应用"**；
- `sys.excepthook` 全局兜底：未捕获异常写入 debug 日志文件并弹友好提示（见 3.11.7）；
- 所有异常统一走日志区 + 总结对话框，不弹裸奔的堆栈。

### 3.6 转换引擎策略（WPS 主引擎 + 纯 Python 兜底，不依赖微软 Office）

**结论先行**：PDF、图片、文本可以完全纯 Python（pypdf / Pillow / fpdf2）；但 **docx / xlsx / pptx 没有保真的纯 Python 渲染方案**（它们是"数据描述"而非"版式成品"，渲染需要完整版面计算引擎；商业库如 Aspose / Spire 有水印或授权成本）。因此采用**WPS 主引擎 + 纯 Python 自动降级**：

```
探测顺序（GUI 可手动锁定任一引擎）：
  1. 后端A WPS COM ──────── 已装 WPS 时最优先（保真度与现状完全一致，含金山专有格式 <现状能力>）
  2. 后端B 纯 Python ───── 无 WPS 或 WPS 转换失败时兜底（图片 Pillow / 文本 fpdf2 / PDF pypdf）
```

| 文件类型 | 后端A WPS | 后端B 纯 Python |
|---|---|---|
| PDF | —（pypdf 直接合并，不转换） | ✅ pypdf |
| 图片 jpg/png/bmp/tif… | ✅ | ✅ Pillow（含 EXIF 方向、多帧 GIF/TIF） |
| txt / log / md | ✅ | ✅ fpdf2（内嵌开源中文字体 + 编码探测，见 3.11.1） |
| doc / docx / rtf | ✅ | ⚠️ mammoth→HTML→WeasyPrint（只建议简单文档） |
| xls / xlsx / csv | ✅ | ❌（openpyxl 无渲染引擎） |
| ppt / pptx | ✅ | ❌（无成熟方案） |
| 金山专有 .wps / .et / .dps | ✅（现状能力） | ❌ |
| 加密 Office（解密后） | ✅ | — |

**配套规则**：

- 引擎选择按文件类型独立决策：Office 文件必须有 WPS，图片/文本无 WPS 时自动走纯 Python；
- WPS 转换失败的图片自动用 Pillow 兜底（原脚本已有此机制，保留）；
- **未安装 WPS 时的处理**：Office 文件明确报"需要安装 WPS（或预先转成 PDF）"，不静默失败；部署面以目标同事均已安装 WPS 为前提（现状即如此）；
- **金山专有格式（.wps/.et/.dps）：已砍掉任何兼容开发投入**——有 WPS 时按现状正常转换（原有能力白拿，不额外开发），无 WPS 时列入"不支持类型"清单并提示需 WPS 转换或预先另存。

### 3.7 输出位置双模式（生成到子目录内 / 统一输出目录）

**用户需求**：生成的成品 PDF 目前固定在对应子文件夹内；需要可选"集中归档"——全部成品统一放进一个新文件夹。

| | 模式A：各子文件夹内（默认，现状行为） | 模式B：统一输出目录（新增） |
|---|---|---|
| 输出位置 | `每个子文件夹 / 【合并】{folder}.pdf` | `指定目录 / 【合并】{folder}.pdf` |
| CLI 参数 | （无，默认） | `--output-dir D:\合并结果` |
| 适用场景 | 资料原地整理、文件夹要带走 | 集中归档、批量交付、统一刻盘/上传 |

**模式B 的四条实现规则**：

1. **自动建目录**：输出目录不存在时自动创建；创建失败（无权限/路径非法）提前拦截并中文提示，不进入任务；
2. **命名冲突自动消解**：输出文件名模板默认 `【合并】{folder}.pdf`；同一批内不同文件夹算出相同文件名时，自动追加序号 `【合并】张三.pdf → 【合并】张三_2.pdf → 【合并】张三_3.pdf`，绝不互相覆盖；历史遗留的旧成品（上次运行生成，带【合并】标记）直接覆盖更新（与模式A语义一致）；日志与总结中如实标注消解后的文件名；**模板变更提示**：用户手工改模板后，上一次旧命名（如无标记 `张三.pdf`）的成品不再被识别为"上次成品"，将按普通素材合并进去——GUI 在模板被修改时提示这一影响；
3. **输出目录排除扫描（关键）**：输出目录可能位于根目录内部（如根目录下的 `合并结果/` 子文件夹），若被扫描：
   - 上次运行的成品 PDF 会被当成素材重复合并；
   - 该目录本身会成为一个"目标文件夹"被单独处理。
   对策：收集阶段（`collect_files` 的 rglob）与目标文件夹枚举阶段（`iter_target_folders`）都按 `resolve()` + `is_relative_to()` 双重排除输出目录整棵树；
4. **上次成品识别**：模式B 下沿用现有的"本次所有计划输出路径集合"（`all_outputs`）判定机制；素材文件夹内历史遗留的"与文件夹同名 PDF"（上次跑模式A留下的）仍按原 lookalike 逻辑跳过，保证 A/B 模式来回切换不会重复合并。

**GUI 交互**：

- 单选"输出位置"：<各子文件夹内> / <统一输出到指定文件夹>；选后者时启用"输出目录"选择框（浏览 + 新建按钮）；
- 预览（dry-run）列表每行末尾显示**成品将写入的完整路径**，两种模式一目了然；
- 完成总结的"打开输出目录"按钮按当前模式定位到对应位置。

### 3.8 增强项设计要点（A 组）

#### 3.8.1 目标文件夹勾选（--only，按相对路径匹配）

- GUI："目标文件夹"区域为多选框列表（默认全选），记忆上次勾选；候选列表随 `--level` 变化；勾选对象是**具体目录条目**，无歧义；
- CLI：`--only` 按**相对路径**匹配（如 `--only 客户A/张三`，可逗号分隔多次）；仅提供文件夹名简写时要求全局唯一，否则报歧义清单并列出候选（见 3.11.5）；
- runner 仅遍历勾选子集，其余逻辑（输出计划、排除规则、报告）完全不变。

#### 3.8.2 运行报告（合并报告.txt）

- 生成时机：全部目标处理结束后，UTF-8-sig 编码（记事本直接可读）；
- 存放位置：模式A＝根目录；模式B＝统一输出目录；固定文件名 `合并报告.txt`（每次覆盖）；
- 内容：运行时间、输出模式与引擎、参数摘要（模板/留白/方向/密码数等）、每个目标（状态/页数/体积/输出路径/使用的引擎）、失败清单（文件+原因+跳过的页数）、跳过的同名 PDF、忽略的不支持类型、总页数与耗时、应用版本号；
- **防误扫规则**：以 `合并报告` 开头的文件在收集阶段一律排除（与 lookalike 同一机制），保证连续重跑不会把上次报告当素材；
- 关闭方式：GUI 取消勾选；CLI `--no-report`。

#### 3.8.3 依赖安装策略（开发/打包分流）

- `deps.ensure_module` 增加入口判定：`getattr(sys, "frozen", False)` 时**不尝试 pip**，直接抛出"应用组件缺失，请重新安装 A4合并助手"；
- 开发模式（`python cli.py` / `python run_gui.py`）保持现有"自动安装 + 清华镜像"逻辑；
- 收益：打包版无 pip、断网、无控制台场景下，不会弹黑框、不会卡死、不会半途失败；
- 开发与打包环境**全量锁定依赖版本**（见 3.11.12）。

### 3.9 明确不做（砍掉项）

为防范围蔓延，以下项**正式砍掉或后置**：

1. **PDF 书签**：不做——合并结果就是连续页面，靠子文件夹顺序与运行报告定位，首版精简（后续按需可加）；
2. **金山专有格式（.wps/.et/.dps）兼容开发**：不投入任何适配/预转换开发；仅保留"有 WPS 时按现状转换"的既有能力，无 WPS 时列入不支持清单并提示（见 3.6）。纯 Python 无解析方案，收益不足以覆盖成本——**永久砍掉**；
3. **LibreOffice 后端**：第一版不做，后置（见第 7 节）——部署面以目标同事均已安装 WPS 为前提，无 WPS 时 Office 文件给出明确提示；
4. **预检清单**：第一版不做——点"开始"直接运行，问题通过实时日志与完成总结暴露（首版精简，后续可加）。

### 3.10 损坏 PDF 容错与失败隔离（单文件失败不连坐）

**问题背景（真实案例）**：某增量保存/修复过的 PDF，第 1 页 `/Annots` 指向对象 47，但对象 47 已被交叉引用流（`/Type /XRef`）复用覆盖，原批注对象不存在、无 `/Rect`。pypdf 6.19 合并该页时无条件取 `a["/Rect"]` 抛 KeyError；而现状代码 `try` 只包了 `transfer_rotation_to_content`，`merge_transformed_page`（处理 `/Annots` 的步骤）**在 try 之外**——单页异常直接中止整个文件夹的合并，42 个正常文件被 1 个坏文件连坐。

**三层防御**：

1. **文件级隔离（已有，保留）**：每个源文件读取 try/except，读取失败 → 进入失败清单 → 继续下一个文件；
2. **损坏页修复（新增，治本）**：合并前 sanitize 该页——遍历 `/Annots`，剔除缺 `/Rect` 或 `/Subtype` 的无效批注项（对象号被复用/损坏的典型表现），过滤后为空则删除 `/Annots` 键，再执行合并；**坏批注去掉，页面内容保留**；
3. **页面级隔离（新增，兜底）**：修复后仍失败的页，记录警告（文件名 + 页码 + 原因）后跳过该页，**继续后续页面与文件，绝不中止整体合并**。

**结果呈现**：成功率不受单文件拖累；结尾汇总（GUI 总结对话框 + `合并报告.txt`）明确列出"未能合并的文件"：文件名、原因、跳过的页数，并提示"其余 N 个文件正常合并"。

### 3.11 工程加固与运维（评审采纳项）

#### 3.11.1 中文字体与文本编码

- **字体**：txt/文本的纯 Python 兜底需要中文字体。禁止直接打包系统字体（如 simsun.ttc，版权风险）；选用**可自由分发的开源字体**（思源黑体 / Noto Sans CJK，SIL OFL 授权），放入 `fonts/` 并经 PyInstaller datas 随 exe 分发（体积约 +20MB，可接受）；fpdf2 加载该字体渲染中文；
- **编码探测**：txt 按 `UTF-8（含 BOM）→ GBK → GB18030` 顺序尝试解码，日志记录实际采用的编码；全部失败时替换乱码字符并警告，不留整页乱码。

#### 3.11.2 图片 EXIF 方向

- 手机拍摄的发票/身份证照片大量带 EXIF 方向标记。Pillow 兜底路径**已使用 `ImageOps.exif_transpose`**（原脚本已有，保留）；WPS 路径由 WPS 自行处理方向；
- 测试矩阵补"EXIF 旋转照片"场景，防止重构时漏掉该处理。

#### 3.11.3 Windows 长路径（260 字符）

- **风险**：深层中文目录 + `【合并】{folder}.pdf` 长文件名，路径容易超 260 字符，导致 rglob 扫不到、输出写失败；
- **对策**：① exe manifest 声明 `longPathAware`；② 启动时探测注册表 `LongPathsEnabled`，未开启时提示"深层目录可能受限，建议项目放浅目录"；③ 关键文件操作（收集/写入/删除）遇到超长路径时尝试 `\\?\` 前缀兜底；④ 仍失败则**明确中文报错**（含完整路径长度），绝不静默失败。

#### 3.11.4 取消的真实粒度

- **问题**：WPS 单批转换最长 600 秒，仅"批间检查"意味着取消最坏等 10 分钟；
- **对策**：`subprocess.run` 改为 `Popen` 持有句柄；取消时**立即 terminate PowerShell 子进程**（连带中断 WPS 的当前转换），随后清理本批临时产物；UI 承诺"点击取消约数秒内响应"；WPS 可能残留的后台 COM 进程由下次启动探测/复用处理。

#### 3.11.5 --only 匹配语义（消除歧义）

- CLI `--only` 按**相对路径**匹配（`--only 客户A/张三`），文件夹名简写仅全局唯一时可用；不唯一时报歧义清单并列出候选；
- GUI 勾选列表以具体目录条目为单位，天然无歧义；
- 测试矩阵补"两个父目录下同名'张三'"场景。

#### 3.11.6 输出模板校验

- 非法字符（`\ / : * ? " < > |`）：GUI 实时校验并拦截（输入框标红 + 提示），CLI 启动时校验并报错退出；
- 未知占位符（如 `{xxx}`）：提示"该占位符不会被替换，将按字面输出"，不静默；
- 模板长度 + 模式B 消解序号联动校验。

#### 3.11.7 诊断导出（排障基础设施）

- **debug 日志落盘**：每次运行写 `%LOCALAPPDATA%\A4合并助手\logs\运行时间戳.log`（与日志区同源），不受日志区 5000 行截断影响；
- **全局兜底**：`sys.excepthook` 捕获未处理异常，写入日志文件并弹友好提示（"发生了意外错误，日志已保存，可点导出诊断包"）；
- **导出诊断包**：GUI 按钮把「debug 日志 + 当前配置（密码脱敏）+ 引擎探测结果 + 系统信息（OS/内存/磁盘/WPS 版本）」打包为 zip，存到用户选择的路径；
- 收益：非技术同事报障＝发一个 zip，远程排障成本降一个数量级。

#### 3.11.8 单实例锁

- QSharedMemory 单实例判定：第二个实例启动时提示"应用已在运行"并激活已有窗口；
- 防两个实例同时写同一根目录/输出目录互相踩；
- 退出时释放共享内存（含异常退出后的自愈：检测残留标记）。

#### 3.11.9 密码存储（DPAPI）

- 默认**不保存**密码（用完即弃）；
- 勾选"记住密码"时才持久化：用 Windows DPAPI（**ctypes 调 `CryptProtectData`**，零额外依赖，不用 pywin32）加密后存 QSettings——本机本用户可解，拷贝到其它机器无效；
- 关于对话框/使用说明注明该特性。

#### 3.11.10 版本信息与分发

- PyInstaller `--version-file` 写入文件属性版本（1.0.0.0）；
- 关于对话框显示：应用版本、构建时间、关键依赖版本；
- 分发方式：**整包替换 exe**（v1 无自动更新），README 写明替换步骤与备份建议；
- 运行报告与诊断包均含版本号，报障时能确认跑的是哪一版。

#### 3.11.11 版本控制与基线

- 工程建 git 仓库，`.gitignore` 排除 `dist/ build/ *.spec` 生成物与日志；
- `merge_to_a4_wps.py` 提交后立即打 tag **`baseline-v0`**（对照基线，永不修改）；
- 每个里程碑结束提交一次；M1 之后每轮回归都在基线 tag 上对照。

#### 3.11.12 依赖全量锁定

- `requirements.txt` 钉死全部版本：`PySide6`、`pypdf`、`Pillow`、`fpdf2`、`msoffcrypto-tool`、`PyInstaller`（+ 传递依赖锁定说明）；
- 打包机使用与开发一致的锁定环境；M5 复现验证时以 requirements.txt 为准；
- 升级依赖＝先改锁、跑 pytest 回归、再进打包。

#### 3.11.13 自动化回归测试（pytest 黄金样本）

- M1 的对照验收**固化为 pytest**：固定样例输入目录 → 断言输出 PDF 的页数、每页尺寸（595.276×841.89pt）、逐页内容流 hash、报告内容与防误扫行为；
- 样例集覆盖：纯 PDF / 混合 Office / 加密 / 损坏 annots / EXIF 旋转 / GBK 文本 / 同名冲突 / 模式A/B；
- 每个里程碑扩展断言集；`tests/` 随 M1 起有真实用例，M5 打包前全量回归绿灯。

| 模式A（默认） | 成品生成在各子文件夹内（`【合并】张三.pdf`），行为与旧脚本一致（仅命名带标记） |
| **输出名标记与模板** | 默认 `【合并】{folder}.pdf`；改模板后冲突消解仍生效；模板变更后旧命名成品不再被识别为上次成品（按素材处理，属预期行为，GUI 有提示） |
| 模式B：统一输出目录 | 所有成品集中在指定目录，自动创建；无散落 |
| 模式B：两个同名子文件夹 | 自动加序号区分（【合并】张三.pdf / 【合并】张三_2.pdf），不互相覆盖 |
| 模式B：输出目录位于根目录内 | 该目录及其内容不参与扫描：不被当素材、不被当目标文件夹 |
| 模式A/B 来回切换重跑 | 上次产物正确识别/覆盖，不重复合并；无"套娃" |
| **--only 勾选** | 只处理选中目标；未选中不在日志与报告中出现；勾选记忆生效 |
| **运行报告** | 模式A/B 均生成 `合并报告.txt`（UTF-8-sig）；连续重跑报告本身不被当素材；含版本号 |
| **打包版断网/无 pip** | 全流程正常，无任何 pip 调用痕迹、无黑框 |
| **pytest 回归** | `pytest tests/` 全绿（含全部上述可自动化场景的断言） |
| dry-run 预览两种模式 | 列出每个成品的完整目标路径 |
| 空文件夹 / 全是不支持类型 | 计入"未生成"，不中断其它文件夹 |
| 运行中取消（批间） | 已生成文件夹保留，不产生半成品 |
| 同名成品 PDF 存在（带【合并】标记） | 默认跳过不重复合并；勾选后包含 |
| 版本信息 | 文件属性与关于对话框版本一致；报障可确认版本 |
| exe 在无 Python 机器上 | 全流程可用 |

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| WPS 后台实例偶发不响应 | 保留原脚本的 3 轮批量重试 + 逐文件兜底机制；图片再走 Pillow |
| 加密 PDF 密码输入在无人值守场景卡住 | 默认勾选"直接跳过"，弹窗有超时跳过 |
| 未安装 WPS 时 Office 文件无法转换 | 启动探测 + 明确提示安装 WPS（部署面以同事均装 WPS 为前提） |
| **长路径超 260 字符** | manifest longPathAware + 系统开关探测提示 + `\\?\` 兜底 + 明确中文报错（3.11.3） |
| **取消响应慢（最坏等满 600 秒批次）** | 取消即 terminate 子进程 + 清理中间产物，承诺数秒响应（3.11.4） |
| **txt 中文乱码 / 字体版权** | 编码探测（GBK→GB18030）+ 内置 OFL 开源字体（3.11.1） |
| **双实例同时写输出** | QSharedMemory 单实例锁（3.11.8） |
| **同事报障信息不足** | debug 日志落盘 + excepthook 兜底 + 诊断包一键导出（3.11.7） |
| **版本混乱无法追溯** | version resource + 关于页版本号 + 报告/诊断包含版本（3.11.10） |
| **回归对照失控** | git 基线 tag `baseline-v0` + pytest 黄金样本（3.11.11/3.11.13） |
| **打包环境不可复现** | requirements.txt 全量锁定（3.11.12） |
| 模式B：同名文件夹输出互相覆盖 | 自动序号消解 + 日志标注；模板可自定义 |
| 模式B：输出目录被误当素材扫描（"套娃"） | 收集与目标枚举阶段双重排除输出目录整棵树（3.7 规则 3） |
| 模式B：输出目录创建失败/无权限 | 启动时提前拦截并中文提示，不进入任务 |
| **合并报告被误当素材** | 收集阶段按名称排除 `合并报告*`（3.8.2） |
| **打包版误触发 pip 安装（黑框/失败）** | `sys.frozen` 分流，打包版直接报错提示重装（3.8.3） |
| 损坏 PDF 拖垮整体合并 | 3.10 三层防御（文件级/页级隔离 + annots 修复） |
| PyInstaller 打包后缺隐藏依赖 | spec 显式收集 Pillow / fpdf2 子模块 + 字体 datas；pytest 全绿后打包 |
| 杀毒软件误报 exe | 建议代码签名或加白名单说明（可后续做） |
| Qt 打包体积大（约 60~100 MB + 字体 20MB） | onefile + upx 可选；可接受则保持 |
| WPS COM 在打包后找不到 ProgID | 启动探测并给出安装指引 |
