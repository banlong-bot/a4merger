# M5 打包版 · 人工异机验收单

> 目的：补上自动化覆盖不到的验收项（计划 4 节 M5 验收标准里"绿色机器 / 未装 WPS 机器实机验证"）。
> 自动化已覆盖并全绿的部分（版本资源、无黑框、单实例、模式A/B、纯 Python 引擎、截图级界面文案）
> 见 `tests/test_frozen_exe.py`，本单只列**必须在别的机器上人工确认**的项。
>
> 建议：A 机＝**干净、无 Python、无 pip** 的 Win10/11 x64；B 机＝**未安装 WPS** 的机器。
> 两台机器都可以没有网络。

## 0. 准备：把文件拷到目标机器

**最省事的做法**：在开发机工程根目录执行

```powershell
python build\make_acceptance_kit.py            # 默认输出到 桌面\A4合并助手-验收包
python build\make_acceptance_kit.py D:\验收包   # 也可指定目录
```

它会：重建测试样例 → 打包 `验收测试数据.zip` → 复制 exe 与本验收单 → 打印指纹与清单。
把这个目录整个拷到 U 盘即可。手工准备的话按下表来。

| 文件 | 从哪拿 | 放到目标机器的位置 |
|---|---|---|
| `A4合并助手.exe` | 工程 `dist\A4合并助手.exe`（指纹见下） | 建议 `D:\A4合并助手\`（放浅目录，便于长路径用例） |
| `验收测试数据.zip` | 开发机执行下面命令生成 | 解压到 `D:\验收测试数据\` |

```powershell
python tests\make_samples.py                      # 幂等重建样例集（32 个文件、约 230 KB）
python -c "import shutil; shutil.make_archive(r'D:\验收测试数据', 'zip', r'tests\samples')"
```

> ⚠️ **不要把 exe 放在 DSH 会话工作区（`C:\Users\25792\Desktop\66`）里再用会话/受限方式启动**：
> 那种启动方式没有可写的临时目录，onefile 解包会失败并报
> `Could not create temporary directory`。**鼠标双击不受影响**，但验收请统一把 exe 放到
> `D:\A4合并助手\` 这类浅目录下再双击（这也是给同事的推荐放置方式）。

开发机当前 exe 指纹（报障时请一并提供目标机器上的指纹）：

```
文件名   ：A4合并助手.exe
大小     ：78,330,554 字节（约 74.7 MiB）
SHA256   ：0EBACE077AD640BA756970E05F651DDB9C69139F5DACE64FB182017488200C87
版本     ：1.0.0.0
```
目标机器上核对：`Get-FileHash .\A4合并助手.exe -Algorithm SHA256`
或右键 exe → 属性 → 详细信息 → 文件版本应为 **1.0.0.0**。

**纪律**：A 机验收期间**不要**安装 Python、不要配置任何环境变量；只跑 exe。

## 2. 全流程（A 机）

### 2.1 正常资料合并（核心用例）

准备 `D:\验收测试数据\正常资料\`（也可以直接用样例里的 `pure_pdf`，它有 张三/李四 两个子文件夹）：

```
正常资料\
  张三\   1.身份证.pdf  2.出资核查.pdf  3.银行流水.pdf
  李四\   1.身份证.pdf  2.核查报告.pdf
  王五\   说明.txt（内容含中文）   扫描件.jpg
```

操作：根目录选 `D:\验收测试数据\正常资料` → 保持默认（模式A、一级子文件夹、模板 `【合并】{folder}.pdf`、勾选"生成 合并报告.txt"）→ 点「开始合并」。

预期：
- 每个子文件夹里生成 `【合并】张三.pdf` 等；**页数 = 该文件夹素材页数之和**；日志绿字「✔ 已生成 …（N 页，X MB）」
- 根目录生成 `合并报告.txt`，双击用记事本打开**不乱码**（UTF-8-sig），含运行参数、目标清单、失败/跳过明细、版本号
- 弹出「运行结果」对话框：成功列表显示 目标/页数/文件大小/输出路径；按钮「打开输出目录」「打开运行报告」「导出失败清单 TXT」「导出运行总结 TXT」
- 双击成功行 → 资源管理器定位到成品
- 把生成的 PDF 打开看：每页为 A4；再次点「开始合并」→ **不重复合并**（成品被识别为上次产物）

### 2.2 统一输出目录（模式B）

操作：选「统一输出到指定文件夹」，填 `D:\验收测试数据\合并结果`（不存在会自动创建）→ 开始。

预期：成品全部集中在该目录 + `合并报告.txt`；**重跑一次不套娃**（页数不变）；若把输出目录设在根目录内部，它不被当素材。

### 2.3 加密文件

把 `验收测试数据\encrypted\`（密码 `123456`）复制成 `D:\验收测试数据\加密资料`：
- 不填密码直接开始 → 弹密码框，输入 `123456` → 正常合并；日志有「密码正确」
- 再建一份副本，弹窗时点「取消」→ 该文件跳过进失败清单，**其它文件仍正常合并**，整体不中断

### 2.4 损坏 PDF 不连坐

把 `验收测试数据\corrupted\` 与任一份正常 PDF 放同一文件夹 → 开始合并。
预期：坏文件被跳过（日志红字 + 失败清单含原因），正常文件照常合并；整体不中止。

### 2.5 取消

用较多 Office 文件的目录（如 `mixed`）开始合并，1~2 秒内点「取消」。
预期：**数秒内**响应结束；无残留转换进程（任务管理器里看不到 WPS 后台进程堆积）；已完成的文件夹保留结果。

### 2.6 结果对话框按钮逐个点一遍

- 「打开输出目录」→ 按模式定位（模式A 打开根目录、模式B 打开统一输出目录）
- 「打开运行报告」→ 定位到 `合并报告.txt`
- 「导出失败清单 TXT」在无失败时应为灰色不可点；有失败时导出后能用记事本打开
- 双击失败行 → 资源管理器选中该文件

## 3. 单实例与长路径（A 机）

| # | 操作 | 预期 |
|---|---|---|
| 3.1 | 双击两次 exe | 第二个实例**快速退出**并提示「应用已在运行」；第一个窗口被激活到前台，不出现两个窗口 |
| 3.2 | 建一个深层目录（用下面脚本），路径长度 **210~250 字符**，里面放 2 个 PDF | 能正常扫描并合并 |
| 3.3 | 同样目录再把名字加长到 **超过 260 字符** | 界面/日志给出**明确中文提示**（提示把资料放浅目录或让管理员开启长路径），**不静默失败、不卡死** |
| 3.4 | 若 3.3 提示"长路径未开启" | 说明系统开关未开；可请管理员开启 `LongPathAware`（注册表 `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem\LongPathsEnabled=1`）后重启再试 |

生成深层目录的小脚本（PowerShell，在**任何**机器都能跑）：

```powershell
$base = "D:\验收测试数据\深层目录"
$p = $base
1..5 | ForEach-Object { $p = Join-Path $p ("深层子目录{0:D2}_ABCDEFGHIJKLMN" -f $_) }
New-Item -ItemType Directory -Force -Path $p | Out-Null
Copy-Item "D:\验收测试数据\正常资料\张三\1.身份证.pdf" $p
Copy-Item "D:\验收测试数据\正常资料\李四\1.身份证.pdf" $p
"当前最长素材路径长度 = " + ((Get-ChildItem $p -File | Select-Object -First 1).FullName.Length)
```

## 验收判定

- **通过**：以上各项全部符合预期（个别"预期"本身描述为提示类，出现正确中文提示即算通过）。
- **不通过**：任一项与预期不符、卡死、崩溃、乱码、生成文件损坏。

## 报障需要提供（5 件套）

1. 出问题的机器：Windows 版本（`winver`）、是否装 WPS、是否装了 Python
2. 你做的操作序列（第几步、点了什么、填了什么）
3. **诊断包**：界面「文件 → 导出诊断包…」的 zip（密码已脱敏）
4. 出问题的素材目录结构（截图或 `tree /f`）、`合并报告.txt`
5. exe 指纹：`Get-FileHash .\A4合并助手.exe -Algorithm SHA256`

若界面卡死点不动：等 30 秒后强制结束进程，然后从
`%LOCALAPPDATA%\A4合并助手\logs\` 取**最新那个 .log** 一起发回（诊断包导出不了时，这个日志就是关键证据）。
