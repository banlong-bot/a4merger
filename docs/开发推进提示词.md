# 《A4 合并助手》LLM 开发驱动提示词（可直接复制使用）

> 用法：三个模板配合使用。
> - 首次启动开发时，把「模板 A」作为第一条消息发给 LLM；
> - 之后每完成一个里程碑，发「模板 B」推进到下一个；
> - 过程中发现问题/想改需求，发「模板 C」。
> 关键纪律：**一次只做一个里程碑**，每个里程碑有自己的验收标准，验收通过才推进。

---

## 模板 A：会话启动（第一条消息，包含项目背景与第一项任务）

```
你是一名资深 Windows 桌面应用开发工程师。现在要依据开发计划，把一个 G 脚本
（merge_to_a4_wps.py，合并 PDF 的工具）重构为 PySide6 桌面应用「A4 合并助手」。

开发纪律（必须无条件遵守）：
1. 每次开始工作前，先读取项目目录下的《A4合并应用开发计划.md》，只执行其中
   指定里程碑的内容，禁止越界做其它里程碑或计划外功能。
2. 如果项目目录存在 PROGRESS.md，先读取它，从上次中断的位置继续；不存在则
   在本次工作开始时创建它（作为跨会话的进度接力文件）。
3. 原脚本 merge_to_a4_wps.py 是"对照基线"，永远不允许修改它的内容；重构时
   从它复制、抽取代码到新工程的 core/ 包。
4. 每个任务结束后：运行 pytest tests/ 确认回归通过（如用例已存在）；
   用 git 提交本次变更（提交信息格式："M{编号}: <一句话描述>"，里程碑完成时打 tag）；
   更新 PROGRESS.md（完成的内容、验证结果、遗留问题、下一步）。
5. 遇到计划文档没有明确写清楚、或实现与计划冲突的决策时，停下来用中文向我
   提问确认，不要自作主张绕过去。
6. 所有界面文案、日志、错误提示一律使用简体中文；代码注释用中文。
7. 只实现，不讨论；不要输出大段解释，工作产出以代码、测试结果和 PROGRESS.md 为准。

现在执行里程碑 M0（环境准备）：
- 在 C:\Users\25792\Desktop\66\ 下建立工程目录 a4merger/（按计划 1.1 节的目录结构）；
- git init 并提交原脚本为基线，打 tag baseline-v0（gitignore 排除 build 产物）；
- 创建 requirements.txt，全量锁定依赖版本（PySide6 / pypdf / Pillow / fpdf2 /
  msoffcrypto-tool / pytest；注意 Python 3.11+）；
- 按计划 4 节 M0 的样例要求，准备 tests/ 下的样例输入目录；
- 完成上述内容后，按纪律 4 收尾并汇报：做了什么、验证结果、下一步。

不要开始 M1。
```

## 模板 B：里程碑推进（每完成一个里程碑，替换 {} 后发送）

```
继续按《A4合并应用开发计划.md》开发。先读取 PROGRESS.md 确认当前进度。

现在执行里程碑 {M1}：{一句话描述，如"核心重构：拆 core 包 + 输出双模式 + 容错"}。

要求：
1. 只做这个里程碑，严格对照计划第 4 节中该里程碑的内容与验收标准；
2. 完成标准＝该里程碑的验收标准全部满足（其中 M1 的对照验证必须给出
   pytest 输出与 内容级一致 的比对结果）；
3. 完成后按纪律收尾：pytest 全绿 → git commit（+tag）→ 更新 PROGRESS.md →
   用以下格式汇报：
   —— 完成项：<列表>
   —— 验收证据：<测试命令与输出摘要>
   —— 遗留问题：<列表，没有则写"无">
   —— 下一步：<建议>
4. 验收未通过时不要进入下一里程碑，先修复。
```

## 模板 C：中途干预（改需求 / 纠错 / 卡住时）

```
暂停当前工作。

请先评估这个调整对当前里程碑和计划文档的影响，用 5 条以内的要点说明
（影响哪些模块、哪些测试用例、工作量变化），然后：
- 如果是计划文档已覆盖的条目，按文档执行并把计划文档对应章节更新为最终状态；
- 如果不确定怎么改，列出你的方案选项让我选择；
- 确认后继续未完成的里程碑。
```

## 使用要点

1. **切片喂上下文**：不要把整份计划一次全塞进去——LLM 每轮只读计划中当前里程碑
   相关章节（模板里已写明"只执行指定里程碑"），配合 PROGRESS.md 接力，能有效
   利用上下文窗口并防止它"跑偏"。
2. **验收是你的刹车**：永远用计划里的验收标准判断"这一轮算不算完"，而不是听
   LLM 自称完成。M1 的验收必须看到 pytest 输出和对基线脚本的内容级一致比对结果。
3. **PROGRESS.md 是接力棒**：这是跨会话（甚至换一个 LLM）继续开发的关键；
   每个新会话开场只要"读 PROGRESS.md 继续"即可。
4. **禁止越界是最高纪律**：LLM 倾向于一口气多做，模板里反复强调"只做当前里程碑"
   和"不要开始下一个"。
5. **git tag 当路标**：baseline-v0 + 每里程碑一个 tag，任何时候可以回退对照。
